# ADVパート 素材規約

サイドビューADVパート（`src/story.js`）が読み込む画像の置き場所と決まりごと。

**ここに置くのは、ゲームが実際に読み込むファイルだけ。** 制作途中のプレビューや
合成見本は `docs/art/` へ置く。読まれないファイルが混ざると、
どれが本番用か分からなくなる。

---

```
├── maps/

│   ├── hill_night/                  … シーン2 収穫祭の夜
│   │   ├── bg_hill_night_far.png
│   │   ├── bg_hill_night_mid.png
│   │   └── bg_hill_night_near.png
│   └── hangar/                      … シーン3 旧ドックの格納庫
│       ├── bg_hangar_far.png        … 全面不透明。この絵の中身は全部ここ
│       ├── bg_hangar_mid.png        … 空
│       └── bg_hangar_near.png       … 空
├── chars/

```

同じ場所でも時間帯が違えば、色替えではなく**マップごと新しいフォルダ**を作る。
`hill` と `hill_night` がその例。

### 層が空でもよい場合がある

`hangar` の mid と near は中身が空だが、これは手抜きではない。

層を分ける目的は「横スクロールしたとき、奥と手前がずれて見えること」。
このマップは `width === BASE_W` の1画面完結なので `camX` が 0 から動かず、
3層に分けても**永久にずれない**。しかも人物は必ず全部の層より手前に描かれる
(`buildStoryScene` が 層 → 人物 の順に足すため)ので、near で人物を隠すこともできない。
つまり今ここで分けても、得るものが何も無い。

将来このマップを横に広げるときは、そのとき初めて far/mid/near を切り出す。

`kobo verify` は空の層を「中身が空(この絵に層は不要)」と表示する。
黙って通さないのは、**層分けに失敗して空になった場合と見分けるため**。

## 命名規則

**1. 版数のサフィックスは付けない。**
`kite_walk_v4.png` ではなく `kite_walk.png`。
どの版かは Git が覚えているので、ファイル名に刻む必要はない。
差し替えるときは正式名のまま上書きしてコミットする。

**2. フォルダの外でも意味が分かる名前にする。**
`hill/far.png` ではなく `hill/bg_hill_far.png`。
エラーログやデバッガにファイル名だけが出たとき、どこの何か分かるようにする。

**3. 種類が名前の先頭に来る。**
`bg_`（背景）/ `prop_`（小物）。人物はキャラ名が先頭。

## パスの参照

**コードにパスを直接書かない。** すべて `src/assets.js` の `ADV_ASSETS` に集約する。

```js
// 良い
storyActorEl.style.backgroundImage = 'url(' + ADV_ASSETS.chars.kite.walk + ')';

// 悪い(フォルダを整理したとき、ここだけ直し漏れる)
storyActorEl.style.backgroundImage = 'url(assets/adv/chars/kite/kite_walk.png)';
```

素材を足したら、まず `src/assets.js` に登録してから使う。

## パレット規約 ― 背景と人物で規約の「種類」が違う

**背景は色の一覧が規約。人物は色相の動かし方が規約。**
同じ物差しを当ててはいけない。

| 対象 | 規約 | 正典 |
|---|---|---|
| 背景（シーン1 林檎の丘） | 原器48色に載っていること | `docs/art/bg_hill_master.png` |
| 背景（シーン2 収穫祭の夜） | 原器48色に載っていること | `docs/art/bg_hill_night_master.png` |
| **人物** | **陰影の作法を守っていること** | `pixel_kobo/shading/hill.json` |
| 小物 | 規格（大きさ・アルファ）のみ | ― |

### 背景 ― 色の一覧が規約

丘の原器48色は**全部暖色**で、緑も青も寒色が1色もない（実測）。
夕焼けの逆光シルエットなので当然だが、これは「全マップ共通のマスターパレット」
としては使えないということでもある。

新しいマップを足すときは、**その絵から48色を抽出して新しい原器にする**。
既存の原器に無理やり寄せない ―― 合わない原器に寄せると色が濁る
（実測：夜の絵を丘の原器に寄せると色域のずれ76.2、自前の原器なら11.5）。

### 人物 ― 色の一覧を規約にしてはいけない

**かつてここには「人物は `palette_char_ramp` の32色だけで作る」と書いてあった。
その規約は守れない。** 実測でこう分かったため：

- そのランプは**32色中28色が暖色**で、寒色は3色（それも輪郭用の暗紫）だけ。
  青緑の服を指定すると、一番近い色が茶色なので**茶色い服になる**
- **既存のカイトと祖父は、色を1つも共有していない**（0/73色）。
  32色ランプに載っているのも23〜40%にすぎない

つまりその規約は、実態を説明してもいないし、守れば全キャラが茶色になる。

**二人が実際に共有しているのは色ではなく、陰影の作り方だった。**

```
カイトの色を明度順に並べたとき、色相がどう動くか

  L69 → H 44°(黄)     L44 → H 28°(橙)     L22 → H  2°(赤)
  L59 → H 30°         L38 → H 26°         L19 → H344°(赤紫)
  L48 → H 38°         L31 → H 21°         L11 → H280°(紫)
                                          L 9 → H265°(青紫)
```

ドット絵で **hue shifting** と呼ばれる古典技法で、
**暗いほど紫へ、明るいほど黄へ**色相をずらす。祖父も同じ動きをしている。

だから人物の規約はこうなる。

- **暗部（明度20未満）の色相が、中間調より紫の方向へ20°以上ずれていること**
- **明部（明度45以上）の色相が、中間調より黄の方向へ2°以上ずれていること**

実測値には十分な余裕がある（既存5枚は暗部へ −52〜−82°、明部へ +14〜+19°）。

この規約なら、青緑の服も白髪も軍装の紺も作れる。
色を選ぶ自由は残しつつ、光の当たり方だけを揃えられる。

小物（脚立など）は色数が少なく明部が存在しないので、この規約の対象外。

### 減色は必ず誤差拡散で

既存の背景は手打ちのドット絵ではなく、**滑らかな絵を640×360に縮小し、
48色へ誤差拡散で落としたもの**（実測：隣り合う画素の52.8%が違う色、
同色が横に続く長さの中央値は1px）。

ディザ無しで減色すると隣接相違率が27.3%まで下がり、明らかに質感が変わる。
誤差拡散なら53.1%で、既存の絵とほぼ一致する。

### 確認のしかた

背景の原器は `.gpl` 形式も `docs/art/` に置いてある。手直しの前に
ペイントソフトへ読み込ませておけば、原器の外の色を使う事故が起きない。

規約を守れているかは工房のコマンドで確認できる：

```
cd ../development_aids/pixel_kobo
python kobo.py verify
```

`src/assets.js` に登録された素材を全部調べる。
背景には原器の準拠率を、人物には色相の動きを出す。

## キャラクター規格

| 項目 | 決まり |
|---|---|
| コマの大きさ | **48×48**（例外: `grandpa_work.png` は鋏を差し出すぶん **56×48**） |
| ピボット | **コマの底辺中央**。この点が地面（`groundY`）に乗る |
| 下の余白 | **0**。足の裏をコマの最下段に接するように描く |
| 向き | **右向きで描く**。左向きは実行時に水平反転して作る |
| 歩きのコマ数 | **4コマ**で1周（＝2歩）。`ADV_CONFIG.WALK_FRAME_COUNT` |
| 歩きの中身 | 4コマのうち2コマは**脚が揃った通過コマ**にする。全コマで同じ足が前だと、足を開いたまま横滑りして見える |
| 身長 | 中身の高さは **46px** 前後（`ADV_CONFIG.CHAR_HEIGHT`） |

コマ送りは時間ではなく**進んだ距離**で進める（`ADV_CONFIG.WALK_STEP_PX`）。
速度をどう変えても足が滑らないようにするため。

### 歩行4コマの正体は3コマ

**実測：`kite_walk.png` も `grandpa_walk.png` も、f1 と f3 が完全に同じ絵。
違う画素はゼロ。** 独立した姿勢は3つしかない（接地A・通過・接地B）。
新しいキャラを作るときも、この構造に合わせる。

頭の上下動（bob）は両者とも **0px**。歩幅はカイトが8px、祖父が10px。

## キャラクターの作り方 ― 基準体（basic_body）

**画像生成AIに歩行4コマを描かせてはいけない。** 4回頼めば4人の別人が出てくる。
コマ間の同一性を保つ仕組みが無いため、これは設定を変えても解決しない。

代わりに、**動きは1度だけ作り込んで使い回す**。
キャラごとに変わるのは色と、ごく一部の画素だけにする。

### 仕組み

基準体は「色を持たない絵」（指標画像）として持つ。1画素が持つのは2つだけ：

```
  R = 領域ID   … その画素が 輪郭 / 髪 / 肌 / 上着 / ズボン / 靴 のどれか
  G = 段       … その領域の中での濃さ（0〜5）
  A = 0 か 255 … シルエット
```

ここへ領域ごとの色を流し込むと絵になる。流す色を変えれば別人になる。
**段の色は書かない** ―― 素材の色を1つ渡せば、上の陰影の作法から生成される。

キャラ定義の実体はこれだけ：

```json
{ "name": "lisbeth", "base": "adult",
  "materials": { "outline": "#a06a52", "hair": "#e0a83c", "skin": "#eda070",
                 "cloth_a": "#4f9e9e", "cloth_b": "#a8404c", "shoe": "#7a5236" },
  "patch": "hat.png" }
```

### これで保証されること

| | |
|---|---|
| 4コマの同一性 | 同じ指標画像を色替えするだけなので、構造上ずれない |
| 規格の適合 | 下余白0・中身の高さ・コマ間のピボット揃いを基準体から継承する |
| 新キャラの手間 | 色を6つ書くだけ。生成し直す必要がない |

### 手順

```
cd ../development_aids/pixel_kobo

python kobo.py body shading                     # 既存キャラから作法を実測する
python kobo.py body extract kite --name adult   # 既存の絵から基準体を起こす
python kobo.py body new <名前> --base adult      # キャラ定義のひな形を作る
  （chars/<名前>.json の materials を書き換える）
python kobo.py body build <名前>                 # コマを書き出して規約を検査する
```

既存キャラを作り直すときは `--from <キャラ名>` を付けると、元の絵から素材色を
逆算する。さらに `--exact` を付けると段の色をそのまま写す
（実測：素材色から生成すると平均色差 36.5/765、段を直接写すと 18.8/765。
ただし `--exact` にすると色替えが効かなくなる）。

### パッチ ― 体つきや持ち物を変える

色替えだけでは「同じ人の色違い」にしかならない。
帽子・髪型・道具のようなキャラ固有の形は**パッチ**で足す。

パッチも指標形式で描く。**色ではなく領域を上書きする**ので、
帽子を `cloth_a` で描いておけば上着と同じ色で塗られ、
`extra_a` で描けば独立した色を選べる。
領域IDを **255** にした画素はシルエットから削られる（帽子で髪を隠すなど）。

シルエットが変わったあと、新しく縁になった画素は自動で輪郭に塗り直される。
これを忘れると、そこだけ輪郭の抜けた絵になる。

下敷きは `python kobo.py body patch --base adult` で出る。

### 拡大について

画面表示は **整数倍のみ**（`floor(画面高 ÷ 360)`）。あまりは黒帯。
補間は禁止（CSS の `image-rendering: pixelated`）。
半端な倍率で拡大するとドットの大きさが揃わず、絵が汚れる。
