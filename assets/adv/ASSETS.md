# ADVパート 素材規約

サイドビューADVパート（`src/story.js`）が読み込む画像の置き場所と決まりごと。

**ここに置くのは、ゲームが実際に読み込むファイルだけ。** 制作途中のプレビューや
合成見本は `docs/art/` へ置く。読まれないファイルが混ざると、
どれが本番用か分からなくなる。

---

## フォルダ構造

```
assets/adv/
├── ASSETS.md                        … このファイル
├── maps/
│   ├── hill/                        … マップ1つにつき1フォルダ
│   │   ├── bg_hill_far.png
│   │   ├── bg_hill_mid.png
│   │   └── bg_hill_near.png
│   └── hill_night/                  … シーン2 収穫祭の夜
│       ├── bg_hill_night_far.png
│       ├── bg_hill_night_mid.png
│       └── bg_hill_night_near.png
├── chars/
│   ├── kite/
│   │   ├── kite_idle.png
│   │   └── kite_walk.png
│   └── grandpa/
│       ├── grandpa_idle.png
│       ├── grandpa_walk.png
│       └── grandpa_work.png
└── props/
    └── prop_ladder.png
```

同じ場所でも時間帯が違えば、色替えではなく**マップごと新しいフォルダ**を作る。
`hill` と `hill_night` がその例。

---

## 命名規則

**1. 版数のサフィックスは付けない。**
`kite_walk_v4.png` ではなく `kite_walk.png`。
どの版かは Git が覚えているので、ファイル名に刻む必要はない。
差し替えるときは正式名のまま上書きしてコミットする。

**2. フォルダの外でも意味が分かる名前にする。**
`hill/far.png` ではなく `hill/bg_hill_far.png`。
エラーログやデバッガにファイル名だけが出たとき、どこの何か分かるようにする。

**3. 種類が名前の先頭に来る。**
`bg_`（背景）/ `prop_`（小物）。人物はキャラ名が先頭。

---

## パスの参照

**コードにパスを直接書かない。** すべて `src/assets.js` の `ADV_ASSETS` に集約する。

```js
// 良い
storyActorEl.style.backgroundImage = 'url(' + ADV_ASSETS.chars.kite.walk + ')';

// 悪い(フォルダを整理したとき、ここだけ直し漏れる)
storyActorEl.style.backgroundImage = 'url(assets/adv/chars/kite/kite_walk.png)';
```

素材を足したら、まず `src/assets.js` に登録してから使う。

## パレット規約 ― 分割方式

**原器は2系統ある。背景と人物で分ける。**

| 対象 | 原器 | 色数 |
|---|---|---|
| 背景（シーン1 林檎の丘） | `docs/art/bg_hill_master.png` | 48 |
| 背景（シーン2 収穫祭の夜） | `docs/art/bg_hill_night_master.png` | 48 |
| **人物・小物（全マップ共通）** | `docs/art/palette_char_ramp.json` | 32 |

### なぜ分けるのか

丘の原器48色は**全部暖色**で、緑も青も寒色が1色もない（実測）。
夕焼けの逆光シルエットなので当然だが、人物までこの48色に寄せると
暖色の背景に暖色のキャラが乗って輪郭が沈む。
しかも夜のマップができるたびに、全キャラの色替え版が必要になる。

人物を独立したランプに乗せておけば、**どのマップでも同じキャラがそのまま使える**。

そのため、**人物・小物が背景の原器と色を共有していないのは違反ではなく仕様**。
（実測：カイト・祖父・脚立は丘の48色と1色も共有していない）

### 守ること

- 背景の新しい素材は、そのマップの原器48色だけで作る
- 人物・小物は `palette_char_ramp` の32色だけで作る
- 新しいマップを足すときは、**その絵から48色を抽出して新しい原器にする**。
  既存の原器に無理やり寄せない ―― 合わない原器に寄せると色が濁る
  （実測：夜の絵を丘の原器に寄せると色域のずれ76.2、自前の原器なら11.5）

### 減色は必ず誤差拡散で

既存の背景は手打ちのドット絵ではなく、**滑らかな絵を640×360に縮小し、
48色へ誤差拡散で落としたもの**（実測：隣り合う画素の52.8%が違う色、
同色が横に続く長さの中央値は1px）。

ディザ無しで減色すると隣接相違率が27.3%まで下がり、明らかに質感が変わる。
誤差拡散なら53.1%で、既存の絵とほぼ一致する。

### 確認のしかた

`.gpl` 形式も `docs/art/` に置いてある。手直しの前にペイントソフトへ
読み込ませておけば、原器の外の色を使う事故が起きない。

規約を守れているかは工房のコマンドで確認できる：

```
cd ../development_aids/pixel_kobo
python kobo.py verify
```

`src/assets.js` に登録された素材を全部調べて、
使用色数・原器内の色数・準拠率と、規格違反の一覧を出す。

## キャラクター規格

| 項目 | 決まり |
|---|---|
| コマの大きさ | **48×48**（例外: `grandpa_work.png` は鋏を差し出すぶん **56×48**） |
| ピボット | **コマの底辺中央**。この点が地面（`groundY`）に乗る |
| 下の余白 | **0**。足の裏をコマの最下段に接するように描く |
| 向き | **右向きで描く**。左向きは実行時に水平反転して作る |
| 歩きのコマ数 | **4コマ**で1周（＝2歩）。`ADV_CONFIG.WALK_FRAME_COUNT` |
| 歩きの中身 | 4コマのうち2コマは**脚が揃った通過コマ**にする。全コマで同じ足が前だと、足を開いたまま横滑りして見える |
| 身長 | 中身の高さは **46px** 前後（`ADV_CONFIG.CHAR_HEIGHT`） |

コマ送りは時間ではなく**進んだ距離**で進める（`ADV_CONFIG.WALK_STEP_PX`）。
速度をどう変えても足が滑らないようにするため。

### 拡大について

画面表示は **整数倍のみ**（`floor(画面高 ÷ 360)`）。あまりは黒帯。
補間は禁止（CSS の `image-rendering: pixelated`）。
半端な倍率で拡大するとドットの大きさが揃わず、絵が汚れる。
